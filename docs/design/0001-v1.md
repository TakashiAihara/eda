# eda v1 design

Status: implemented in the first PR. Requirements and the decisions behind them (D-01..D-09) were settled before this repo existed; they are summarized under "Decisions carried in".

## Background

- Previous attempts at "make a mind map with an AI" ended with the AI generating a huge map in one go, leaving no room for the person to think.
- eda is a mind map where the AI can only *suggest one node at a time*, and a person adopts or rejects each one.
- The person consults with the same Claude Code session they are already working in, from the map screen.

## Conclusion

- A local Bun server owns the map. The browser and Claude Code both go through it.
- Claude Code's only interface is an MCP server (`eda mcp`) with four tools, none of which write the map: `read_map`, `suggest_node`, `suggest_edit`, `reply`.
- `map.md` is an export only: eda rewrites it at start and on every save and never reads it back. The map changes only through the UI (#5).

## Storage

- A map is a directory. `eda.json` is the source of truth; only the server writes it.
- `map.md` is `# root` followed by 2-space nested bullets, readable by Markmap and Obsidian. A node's URLs follow its text as markdown links and its note follows as a quote, which Markmap draws inside the node (a root's note it does not draw); kaneo tasks and markers are not exported (#35). An IPv6-literal URL does not open from Markmap: markdown-it encodes its `[` and `]`.
- `map.md` is rewritten at start and on every save, and never read. A hand edit stays in the file until the next start or save writes over it. A directory that holds a `map.md` but no `eda.json` is refused at start, so a person's file is not overwritten by an empty map.
- Maps saved before #5 can still hold `md-edit` candidates and nodes; they are adopted and shown as before.
- The Claude Code sessions that touched the map are listed in `eda.json` and shown in the header as `claude --resume <id>`.

## Structural limits on the AI

- MCP exposes no write tool. Adoption, deletion, URL/task edits are browser-only routes.
- Up to three AI suggestions per (session, model) can be pending, so the person can weigh a few side by side; the fourth call gets 409 until the person adopts or rejects one.
- A suggestion is exactly one node (`suggest_node`) or one node's change (`suggest_edit`).
- A node takes one pending edit at a time, from any session or model; the second gets 409. The map marks a node with one ring, and adopting both would overwrite the first without saying so (#22).
- The person's routes and the AI's routes take different tokens (#2): the MCP server reads `~/.eda/ai-token`, which opens only `/api/ai/*`; the browser's `~/.eda/token` opens everything else and none of `/api/ai/*`.
- Known limit: Claude Code still runs as the same OS user, so with the shell it can read `~/.eda/token`. The MCP instructions also ask the session to start the map and pass on the URL `eda serve` prints, which carries the person's token, so on the documented path the session sees it. The tools do not use it; closing this would need a URL without the token, or a credential the agent's OS user cannot read.
- Known limit: the `x-eda-session` header is taken as sent, so any holder of `ai-token` can act as any session.
- Known limit: `eda.json` edited by hand while the server runs is overwritten on the next write; edited while it is stopped, it is the map.

## Decisions carried in

- D-01 personal tool, public repo: machine-specific things are configuration (`~/.config/eda/config.json`, `EDA_KANEO_HOST`, `EDA_HOME`).
- D-02 standalone web app (local server + browser).
- D-03 / D-08 the server owns the map; `map.md` is an export. External edits were candidates until #5 (judgment queue D-02, 2026-10-11: the map is not operated from outside the UI); now they are not read.
- D-04 the consulting partner and the suggester is the same Claude Code session.
- D-06 task links per node, any project, stored as ids.
- D-07 URLs only in v1.
- D-09 MCP: read, suggest a node, suggest a change to a node.

## Decided here

- `reply` is a fourth MCP tool so the session can answer in the map's chat. It does not touch the map. (Open for the owner: judgment queue D-10.)
- Frontend is plain TypeScript and CSS bundled by Bun's HTML import; the tree is nested lists drawn with CSS borders, so there is no runtime dependency. Rendering libraries (markmap and the like) were not evaluated; revisit when the layout needs to go beyond a left-to-right tree.
- Auth is two bearer tokens per host: the person's (`~/.eda/token`, passed to the browser in the URL fragment) and the MCP server's (`~/.eda/ai-token`). Same level as akapen.
